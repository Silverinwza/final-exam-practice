# แบบจำลองสอบปฏิบัติ Express + MySQL + Jest

ชุดฝึกที่สร้างจากเอกสารในเครื่อง ไม่ใช่ข้อสอบจริงและไม่รับรองว่าจะออกตามนี้ โจทย์จริงยังไม่ได้แจก ใช้ฝึกก่อนสอบตามขอบเขตที่ผู้ใช้ขอ

เริ่มจาก **โจทย์จำลอง.md** แล้วแก้ใน `starter/` ถ้าต้องการดูวิธีทำให้อ่าน **เฉลยอธิบาย.md** และ `solution/`

## ติดตั้งและรันบน PowerShell

Docker Desktop ต้องเปิดอยู่ และ MySQL ของ final-exam-setup ต้องทำงานที่พอร์ต 3309 (ตัวเดียวกับที่เตรียมไว้ก่อนหน้า)

```powershell
cd "C:\Users\OS\Documents\Codex\2026-11-01\new-chat\outputs\final-exam-practice"
# ถ้า node_modules ยังไม่มี หรือย้ายชุดฝึกไปเครื่องอื่น
npm.cmd install
# ทำครั้งแรก: คัดลอกถ้ายังไม่มี .env
Copy-Item .env.example .env
npm.cmd run seed
npm.cmd test
```

ในเครื่องนี้ได้เตรียม .env และแพ็กเกจให้แล้ว `npm.cmd run seed` จะสร้าง/รีเซ็ตเฉพาะ `exam_practice_db` และเติม 22 เมนู กับ 3 ออเดอร์ตัวอย่าง ตารางเหมือนชุดติดตั้งของผู้สอน คำสั่งนี้ล้างข้อมูลซ้อมเดิมทุกครั้ง ไม่ต้อง seed ซ้ำก่อนเทสต์แต่ละรอบ

```powershell
# ตรวจเฉลยทั้งหมด รวม MySQL จริง
npm.cmd test
# เฉพาะเทสต์แบบ mock ไม่ต้องเปิด MySQL
npm.cmd run test:unit
# ตรวจโค้ดที่ตัวเองแก้ใน starter (ตอนเริ่มต้นควร FAIL หลายกรณี)
npm.cmd run test:practice
# ดู coverage ของเฉลย
npm.cmd run test:coverage
# เปิด API เฉลยที่ localhost:3010
npm.cmd start
# หรือเปิด API ที่กำลังฝึกแก้แทน (เลือกเปิดทีละตัว เพราะใช้พอร์ตเดียวกัน)
npm.cmd run start:practice
```

หากต้องเปิด MySQL ใหม่ ให้เข้าโฟลเดอร์ `final-exam-setup` แล้วรัน `docker compose up -d` จากนั้นกลับมาชุดฝึกนี้

## โครงสร้าง

| ไฟล์/โฟลเดอร์ | ใช้ทำอะไร |
|---|---|
| โจทย์จำลอง.md | คำถาม 3 ข้อและเกณฑ์ 6–4–5 คะแนน |
| แผนอ่านเอกสาร.md | เอกสารที่พบ พร้อมหัวข้อที่ควรเปิดทบทวน |
| starter/menu.js | โค้ดมีบั๊กสำหรับข้อ 2 |
| starter/orders.js | โค้ดมีบั๊กสำหรับข้อ 3 |
| starter/tests/menu.test.js | โครงให้เขียนเทสต์ข้อ 1 |
| solution/ | เฉลยโค้ดและเทสต์ข้อ 1 |
| checks/ | เทสต์ตรวจข้อ 2–3 ที่ให้มาพร้อมโจทย์ |
| common/ | app factory และ validation ของ request body ที่ให้มาแล้ว |
| เฉลยอธิบาย.md | เหตุผล วิธีอ่าน failure และแนวคำตอบอธิบาย |

`test:practice` รวมเทสต์ที่เขียนเองใน starter/tests กับ checks ข้อ 2–3 ส่วน `test` ใช้เทสต์เฉลยกับ checks เดียวกัน การมี `todo` ไม่ถือว่าทำข้อ 1 เสร็จ ต้องเปลี่ยนเป็น test จริงครบทุกกลุ่ม

เทสต์ integration สร้างข้อมูลชื่อเฉพาะรอบการรันและลบเฉพาะข้อมูลของตัวเองเมื่อจบ ต้อง seed ก่อนครั้งแรก ส่วน mock จำลอง DB เพื่อควบคุมกรณี error และตรวจ SQL parameters จึงไม่ได้พิสูจน์พฤติกรรม SQL จริงทุกเงื่อนไข

เอกสารแนวสอบที่อ่านกำหนดให้วันสอบไม่ใช้ AI ช่วยตอบหรือเขียนโค้ด ชุดนี้จึงใช้สำหรับซ้อมและทำความเข้าใจก่อนสอบ
